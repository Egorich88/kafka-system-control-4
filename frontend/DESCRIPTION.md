## Страница Overview — Обзор кластера

Главная страница мониторинга Kafka System Control. Предназначена для
оперативной оценки состояния Kafka-кластера и быстрого перехода от
общего состояния к конкретной проблеме.

### Структура страницы

1. **KPI-карточки** — количество брокеров, топиков, партиций, Consumer Groups,
   входящий и исходящий поток сообщений, количество недореплицированных
   партиций.
2. **Состояние кластера** — фактический статус `Healthy / Warning / Critical`
   и компактная информация по брокерам: ID, адрес, доступность, ISR,
   контроллер, лидеры, реплики, CPU, память, диск и версия Kafka.
3. **Распределение партиций** — двухуровневая кольцевая визуализация:
   роли Leader/Follower и отдельно состояние Healthy/Under Replicated/Offline.
   Два кольца используются потому, что роль реплики и состояние партиции
   не являются взаимоисключающими показателями.
4. **Consumer rate / Producer rate** — компактные графики текущего
   исходящего и входящего потока сообщений.
5. **Пропускная способность кластера** — историческая динамика входящих
   и исходящих сообщений.
6. **Пропускная способность по топикам** — историческая скорость обработки
   отдельных топиков. Цвет каждого топика стабилен между графиком и легендой.
7. **Группы потребителей** — общий график lag и таблица Group + Topic.
   Для каждой связки отображаются состояние группы, lag, изменение и
   последнее наблюдаемое время активности.
8. **Последние события** — оперативная лента изменений кластера. Для событий
   Consumer Groups дополнительно выводятся группа, топик и состояние.

### Статусы Consumer Group

- `Stable` — группа активна, консьюмеры подключены и партиции распределены.
- `Rebalancing` — выполняется перераспределение партиций.
- `Empty` — у группы нет активных участников.
- `Dead` — группа больше не активна и её метаданные удаляются.

Статус Consumer Group является свойством группы целиком. В таблице Overview
он повторяется для каждого топика, который связан с данной группой, чтобы
lag конкретного топика можно было сразу сопоставить с состоянием группы.

### API Overview

- `GET /api/overview` — агрегированные KPI.
- `GET /api/overview/health` — состояние кластера, брокеров, ISR и партиций.
- `GET /api/overview/throughput` — историческая пропускная способность.
- `GET /api/overview/topics-throughput` — историческая пропускная способность топиков.
- `GET /api/overview/consumer-lag` — история lag и текущие строки Group + Topic.
- `GET /api/overview/events` — последние события.

Все Kafka-запросы страницы используют выбранный кластер через заголовок
`X-Kafka-Bootstrap`.
