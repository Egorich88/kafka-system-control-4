Odyssey — современный веб-интерфейс (Kafka Control Panel) для администрирования
Apache Kafka. Построен на Go и React с нуля: от консольных утилит до
production-готового микросервиса с CI/CD, контейнеризацией, уведомлениями
о релизах и деплоем в Kubernetes.

> Раньше проект назывался Kafka System Control (KSC). Новое имя — Odyssey —
> отражает суть инструмента: быть надёжным штурвалом и картой для инженера
> в бушующем море данных Apache Kafka.

## 🌊 Почему Odyssey

**Сильный бренд вместо «безликости»**

Kafka System Control отлично описывало техническую суть, но звучало серо и
громоздко. Odyssey — короткое, запоминающееся имя, которое легко пишется
в консоли, быстро гуглится и сразу формирует уникальный бренд.

**Метафора для SRE и DevOps**

В греческой мифологии Одиссей — великий штурман и капитан, прошедший сквозь
рифы, шторма и ловушки бушующего моря. Apache Kafka — это то самое огромное
и непредсказуемое море данных, где каждый день штормит от лагов консьюмеров,
падения брокеров и просроченных SSL-сертификатов. Odyssey выступает в роли
надёжного штурвала и карты для инженера.

**Дух соло-разработки**

Одиссей полагался на собственную хитрость и интеллект, побеждая там, где
пасовали целые армии. Это отражает ДНК проекта: он ведётся одним инженером,
выступающим одновременно архитектором, бэкендером и фронтендером.

**Чёткое позиционирование**

Слово System в старом названии могло путать: администраторы могли подумать,
что проект — замена Apache Kafka. Новое позиционирование Odyssey —
**Kafka Control Panel** — сразу заявляет, что это визуальный, лёгкий и мощный
инструмент контроля, анализа и управления.

## ✨ Возможности и статус разработки

### ✅ Готово

- **Интуитивный UI** — тёмная и светлая темы, боковое меню, переключение между несколькими кластерами Kafka.
- **Сайдбар** — полностью переработан: сворачивание, логотип быстрого переключения тем (светлая/тёмная).
- **Собственный логотип** — фирменный знак Odyssey.
- **Страница загрузки** — отображается внутри страниц при переходе.
- **Верхняя горизонтальная панель** — для страниц с возможностью выбора периода отображения и времени автообновления.
- **Управление топиками** — просмотр, создание, удаление, изменение конфигурации (retention, cleanup.policy и др.).
- **Поиск сообщений** — чтение сообщений из выбранной партиции с фильтром по offset и лимиту.
- **Многокластерность** — добавление кластеров с разными типами аутентификации (PLAINTEXT, SASL/SCRAM, mTLS в плане).
- **Уведомления о релизах** — автоматическая рассылка в Telegram и MAX при выходе новой версии, со скриншотом и changelog.
- **CI/CD из коробки** — сборка, публикация образов в Docker Hub и создание GitHub Release при пуше тега.
- **Контейнеризация** — готовые Docker-образы для бэкенда и фронтенда.
- **Развёртывание в K8s** — манифесты и Terraform для Yandex Cloud.

### 🔄 В работе

- **Overview (дашборд)** — готов на ~90%. Осталось: подключить бэкенд к панели
  «Сертификаты Kafka», небольшие визуальные доработки интерфейса, добавить
  уровень `critical` в панель «Последние события», переработать панель
  «Состояние кластера», панель «Группа потребителей» изменена — добавлены
  статусы и обновлено отображение.
- **Аудит** — готов на mock-данных, остались небольшие правки.
- **Топики** — работает. Требуется добавить создание сообщения (либо на этой
  странице, либо в «Поиске сообщений»).
- **Пользователь** — на mock-данных.
- **Настройки** — выбор языка интерфейса (пока добавлен только английский),
  различные известные темы оформления.
- **Страницы с mock-данными** — ksqlDB, Schema Registry, Kafka Connect.

### ⏳ В разработке

- **Страница «Брокеры»**.
- **Страница «Оповещения»**.
- **Страница «Консоль»** (web-shell для Kafka CLI).
- **ACL** — управление списками контроля доступа.
- **Управление группами потребителей** — просмотр, сброс офсетов.

## 🚀 Быстрый старт

### Локальная разработка

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Egorich88/kafka-system-control-4.git
   cd kafka-system-control-4

2. **Запустите бэкенд (требуется работающая Kafka на localhost:9092)**
   ```bash
   cd backend
   go run main.go
   
3. **Запустите фронтенд (в другом терминале)**
   ```bash
   cd frontend
   npm install
   npm run dev

4. **Откройте http://localhost:5173 – интерфейс готов к работе.**

## Docker Compose (всё в одном)
  ```bash
   docker-compose up --build
   ```
  - Фронтенд: http://localhost:5173
  - Бэкенд: http://localhost:8080/api/topics

## 🔁 CI/CD (GitHub Actions)
Workflow разделён на три независимых job'а:

- verify — запускается на push в main. Только собирает backend и
frontend, чтобы убедиться, что код компилируется. В Docker Hub ничего не
публикуется.

- release — запускается только на тег v*. Собирает и публикует образы
в Docker Hub, создаёт GitHub Release.

|🧪deploy-to-kubernetes — запускается только вручную через
workflow_dispatch с флагом deploy=true.

Публикация образов:

- egorich27/kafka-control-backend

- egorich27/kafka-control-frontend

## 🔔 Уведомления о релизах
При выходе нового тега v* автоматически отправляется уведомление в два канала:

- Telegram — сообщение с описанием изменений и скриншотом релиза.

- MAX — сообщение с описанием изменений и вложенным изображением.

Уведомления формируются из коммитов между предыдущим и текущим тегом.
Скриншоты хранятся в docs/screenshots/ и подхватываются по имени, совпадающему
с тегом (например, v4.2.24.png).
